# Infrastructure

Static SPA hosting for [starter-pack](https://starter-pack.603.nz), managed
with Terraform. Cloudflare keeps `603.nz` DNS pointed at the CloudFront
distribution, AWS CodeBuild is the deployment runner.

## What is managed

**Static hosting** (`module.web_app`)
- Private S3 bucket (BucketOwnerEnforced, no public ACLs)
- CloudFront distribution fronting S3 via Origin Access Control
- SPA fallback: 403/404 → 200 `/index.html`
- Modern TLS (TLSv1.2_2021), AWS-managed `CachingOptimized` cache policy

**TLS** (`module.acm_certificate`, `aws_acm_certificate_validation` in us-east-1)
- Per-host ACM cert for `starter-pack.603.nz`, DNS-validated through
  Cloudflare via the shared `cloudflare-dns-records` module
- Cert managed by `acm-dns-validated-certificate`; the
  `aws.us_east_1` provider alias is wired to the module

**DNS** (`module.dns_validation_records`, `module.dns_app_records`)
- Validation CNAMEs created up-front so the cert can validate
- App `CNAME starter-pack.603.nz → <cloudfront domain>` created after
  CloudFront so it can target the distribution domain (DNS-only, not proxied
  — CloudFront terminates TLS for the alias)

**CodeBuild deployment** (`module.codebuild_role` + `module.codebuild_deploy_project`)
- `starter-pack` builds the SPA, applies Terraform, syncs `dist/` to S3 and
  invalidates CloudFront
- IAM role and inline policy generated by the shared
  `codebuild-terraform-role` module — CloudFront, deployment-bucket, and
  CodeBuild-cache permissions are passed via `additional_policy_statements`
- Webhook triggers on pushes to `typescript`

**SSM token placeholders** (`ssm-parameter-placeholder`)
- `/starter-pack/cloudflare-api-token` — Cloudflare API token (secret)
- `/starter-pack/ga-id` — Google Analytics ID (kept in SSM matching original buildspec)

`AUTH0_CLIENT_ID`, `AUTH0_DOMAIN`, `REMOTE_STATE_BUCKET`, `APP_HOSTNAME`,
`DEPLOYMENT_BUCKET`, region, and TF state key are plaintext build env vars in
`buildspec.yml` — they are not secrets.

Terraform does not take a plaintext `cloudflare_api_token` variable.
CodeBuild loads `CLOUDFLARE_API_TOKEN` from SSM into the environment so the
provider can authenticate without storing the decrypted token in Terraform
state.

## State

Remote state is stored in S3:
`s3://jch254-terraform-remote-state/starter-pack-prod-infrastructure`
(ap-southeast-4, encrypted).

## Module versions

This repo expects shared `terraform-modules` tag `1.17.0` or newer for the
modernised `web-app` module (private S3 + Origin Access Control, no Route 53).

## Bootstrap (first apply)

The modules reference `?ref=1.17.0` of `jch254/terraform-modules`. Tag and
push that release before the first `terraform apply` — the bootstrap apply
creates the SSM placeholders, then the placeholders need real token values.

```bash
cd infrastructure/terraform

# Authenticate with AWS (requires access to the S3 state bucket)
aws sso login  # or export AWS_* env vars

# For the first local/bootstrap apply, export a real Cloudflare token directly.
export CLOUDFLARE_API_TOKEN="..."

terraform init
terraform plan
terraform apply
```

After the bootstrap apply, populate the secret placeholders:

```bash
aws ssm put-parameter --region ap-southeast-4 \
  --name /starter-pack/cloudflare-api-token \
  --type SecureString --value "$CLOUDFLARE_API_TOKEN" --overwrite

aws ssm put-parameter --region ap-southeast-4 \
  --name /starter-pack/ga-id \
  --type SecureString --value "$GA_ID" --overwrite
```

The Cloudflare token needs Zone DNS Edit on `603.nz`.

## CodeBuild flow

`buildspec.yml` runs:

1. `corepack enable` + `corepack prepare pnpm@9.15.9 --activate`, then `pnpm install --frozen-lockfile`
2. `infrastructure/deploy-infrastructure.bash` — `terraform init` / plan / apply (with IAM-first apply on first run)
3. `pnpm run build` — produces `dist/`
4. `infrastructure/deploy-artifacts.bash` — `aws s3 sync dist/` + CloudFront invalidation

CodeBuild reads `DEPLOYMENT_BUCKET` and `CLOUDFRONT_DISTRIBUTION_ID` from
Terraform output (or env), so the artifact step does not depend on local
state outside the build container.

If automatic push deploys are enabled, the AWS account also needs CodeBuild's
GitHub source connection/credentials configured for webhook creation.
